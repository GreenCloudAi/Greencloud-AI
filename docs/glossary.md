# GreenCloud AI Glossary of Technical Terms

This document provides concise, plain-language definitions for technical terms, frameworks, formulas, and abbreviations used across GreenCloud AI documentation and reports.

---

## 1. Domain Operating Models

### FinOps (Financial Operations)
An operational framework and cultural practice for cloud cost management that enables engineering, finance, and business teams to collaborate on data-driven cloud spending decisions.

### GreenOps (Green Operations)
An operational practice focused on measuring, tracking, and reducing the environmental carbon emissions generated by cloud computing resources and software applications.

---

## 2. Industry Standards and Protocols

### FOCUS (FinOps Open Cost and Usage Specification)
An open standard that normalizes cloud billing data schemas across AWS, Azure, Google Cloud, and SaaS providers into a uniform dataset structure.

### GSF (Green Software Foundation)
A non-profit standardization organization under the Linux Foundation that defines standards, tooling, and best practices for green software engineering.

### SCI (Software Carbon Intensity)
A Green Software Foundation standard formula for calculating software carbon emissions:
`SCI = (Operational Emissions + Embodied Emissions) / Functional Unit`

### GHGP (Greenhouse Gas Protocol)
The global standard accounting framework for measuring and managing greenhouse gas emissions across Scope 1 (direct), Scope 2 (indirect electricity), and Scope 3 (value chain).

---

## 3. Carbon Measurement Concepts

### Operational Carbon (Operational Emissions)
The greenhouse gas emissions caused directly by the electricity consumed while cloud servers, storage, and networking hardware execute software workloads.

### Embodied Carbon (Embodied Emissions)
The estimated portion of greenhouse gas emissions generated during the raw material extraction, manufacturing, transport, and disposal of physical cloud server hardware, allocated over its operational lifespan.

### Carbon Intensity
The amount of carbon dioxide equivalent emitted per unit of electricity generated, expressed as `gCO2e / kWh`. Carbon intensity varies continuously by geographical grid location and time of day.

### Functional Unit
The unit of business measurement used to normalize carbon intensity output in the SCI equation, such as `per active user`, `per API request`, `per database query`, or `per transaction`.

---

## 4. Technical Architecture and Data Components

### Resource Graph Service
A time-aware graph data model that maps cloud resource relationships, linking accounts, regions, Kubernetes namespaces, deployments, pods, ownership tags, and business units.

### RAG (Retrieval-Augmented Generation)
An artificial intelligence pattern that retrieves relevant internal documentation, historical telemetry, and vendor guidelines to ground large language model responses in verified evidence.

### Policy-as-Code
The practice of defining infrastructure governance rules, security constraints, and automation policies using declarative code files (such as OPA/Rego or Cloud Custodian YAML).

### ReAct Agent (Reasoning and Acting)
An AI agent architecture pattern that combines step-by-step reasoning with execution tools to perform complex multi-step technical workflows.

### Dry-Run Simulation
An execution phase that evaluates the outcome and potential impact of a recommended infrastructure change in a safe, non-destructive test environment before applying modifications to live production resources.

---

## 5. Optimization Strategies

### Rightsizing
The process of adjusting cloud compute instances, containers, storage volumes, or database allocations to match actual historical utilization telemetry without violating performance SLOs.

### Idle Resource Cleanup
The automated identification and deprovisioning of unattached or unused cloud assets, such as unattached disks, unassociated Elastic IPs, idle load balancers, and stopped instances.

### Carbon-Aware Scheduling
Shifting non-urgent or batch computing jobs to times or geographical regions where the electricity grid carbon intensity is lowest.

### Showback and Chargeback
- **Showback**: Reporting cloud resource spending to specific teams or business units for visibility and awareness.
- **Chargeback**: Directly billing cloud resource spending back to the budget of the team or department that incurred the cost.

### Post-Change Verification Loop
An automated monitoring mechanism that tracks application health, performance SLOs, costs, and carbon output following an infrastructure change execution. If performance degrades, an automated rollback is triggered.
